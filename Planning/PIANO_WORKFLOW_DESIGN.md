# 钢琴编配工作流设计草案

日期：2026-10-10；状态：**仅规划，待评审，未实施**。入口见 [总览](README.md)，执行拆分见 [TODO](TODO.md)，当前能力与引用见 [研究记录](RESEARCH.md)。

## 1. 范围、取舍与修改量

目标是减少编配时的理论核对、试写切换、表达录入和视频后处理负担。传统算法优先，AI 留为可替换的后续 provider；不要求提供原曲才可使用。功能按领域独立组织，不把所有东西塞进 HarmonyAssistant，也不替换原有钢琴键盘、演奏编辑器、谱面选中和播放系统。

| 子功能 | 首选路线 | 工作量 / 合并风险 | 升级到原生的明确理由 |
| --- | --- | --- | --- |
| 选区和声/对位疑点、基础跨度 | 插件 | M / 低 | 只读 API 缺少关键对象时补快照字段；不是把规则搬进核心 |
| 指法、分手、配音候选 | 插件 + 可选本地计算服务 | L / 低至中 | 受保护批量应用、跨声部改谱确有 API 缺口 |
| 视频 MIDI 派生输出 | 离线工具；插件入口可选 | M / 低 | 仅为取得有效演奏导出、便利入口或导出映射补桥 |
| 方案副本管理 | 插件原型 | M / 低至中 | 现有保存/打开接口无法保证副本无副作用，或标签页体验不满足需要 |
| 同窗口方案工作区 | 插件 + 薄宿主模块 | L / 中 | 独立谱实例的生命周期、当前视图/播放绑定、安全切换 |
| 核心模型内置多版本小节 | 深改软件 | XL / 高 | 本轮不推荐；涉及模型、格式、排版、Undo、分谱与播放，不适合个人功能起步 |
| Tap BPM | 小型原生模块 | S / 低 | 准确放在原生节拍器旁，复用 QAction 与节拍器设置 |
| 导入演奏 MIDI 并对齐 | 插件 + 离线计算 | M–L / 低 | 应用速度/力度时可能需原生通用编辑桥 |
| 实时演奏捕获 | 插件 + 宿主捕获模块 | L / 中 | 后端时间戳、单设备所有权、隔离正常输入与捕获模式 |
| 基础参考播放器 | 插件原型，媒体部署通过后定路线 | M / 低至中 | QML 媒体后端不足，或需要可靠的停靠/定位桥 |
| 频谱、谱段定位与同步 | 插件 + 媒体宿主/工作线程 | L / 中 | 异步解码、缓存、稳定运输控制；不进入音乐模型 |
| 联合音频引擎、任意实时变速/边播边切方案 | 深层音频改造 | XL / 高 | 远期另立任务，不作为前面功能的前置依赖 |

S/M/L/XL 是相对工程复杂度，**不是工期承诺**。S 为独立模块及少量接线；M 含数据格式/局部 UI/算法测试；L 涉及跨组件状态与失败恢复；XL 涉及多个核心子系统。原生修改的控制目标：新增独立模块、工厂/构建接线和少数现有入口；以原型结果核定实际文件数，不预先承诺固定行数。

## 2. 共同数据与运行基础

### 2.1 不混淆四种数据

1. **谱面事实：** 当前内存谱的每个音、声部、拼写、起止、休止、延音线、拍号、速度、踏板、演奏参数、分手/指法标记。未保存修改也必须读到。
2. **解释：** 和弦、级数、角色、指法建议、难度、疑点。多种解释可以并存，用户选择的解释仍有来源与范围。
3. **演奏/参考材料：** 录入 MIDI、原曲音频、外部和弦表或旋律，可仅覆盖一段，也可缺失。
4. **候选与派生输出：** 替代配音、方案副本、视频 MIDI、力度/rubato 草稿。不自动变成原谱事实。

沿用既有 MCP 设计中的 `scoreSnapshot / assertions / materials / alignments / taskBrief / analysisRuns / proposals`，见 [衔接依据](RESEARCH.md)。模块名、接口字段和状态在本文件中均为提议，不代表现有软件已开放。

### 2.2 最小快照及定位

- 标头带 schemaVersion、documentId、scoreSessionId、snapshotId、scope、coverage、capabilities。区分“不提供”“没有”“不支持”“读取失败/未处理”“过期”。
- 保留完整复调事件，音高 MIDI 与 TPC/记谱音高分开；同音不同声部不合并。延音线关联为一次逻辑攻击，但保留每个谱面音定位。
- 时间同时区分有理数谱拍/tick、展开反复后的演奏位置、真实秒、MIDI 文件 tick/PPQ。只在明确转换处换算；不能拿 NoteEvent 千分比当 MIDI tick。
- 定位可暂用 tick/track/index + pitch/TPC，应用前用原快照及旧值校验。它不是跨任意编辑永久稳定的音符 ID。
- 当前 ScoreObserver 的上下文摘要适合和声助手，不能替代全对象快照；现有 fingerprint 也不能验证所有指法/力度/布局修改。
- 演奏编辑器未提交的预览需明确纳入候选，或先提交/丢弃后再捕获事实；不把屏幕预览颜色、拖动草稿当作保存数据。

### 2.3 存储与共享

插件配置保存预设、个人舒适跨度、视图和快捷操作；分析会话/材料/方案另存版本化旁车文件或工作区。文件关联支持移动后重新定位，不只依赖绝对路径；保存摘要与源版本，失效时重算/重关联，不静默套用。

轻量规则与 Tap 可完全独立工作；大型指法/对齐/频谱可使用本地辅助进程。若已有 MCP context service，则复用 schema 和结果格式；不要求开网络服务、连接 LLM 或填完全部资料。只读快照出 GUI 线程，工作线程/外部进程不得持有 libmscore 对象指针。

### 2.4 修改与预览边界

分析纠正、增添原生和弦记号、修改实际音符是不同动作。候选带 parentSnapshot、editableScope、protectedRefs、expectedOldValues、依赖材料版本和变化摘要。应用用原生编辑操作，预检后写回、读回核对，并验证一次操作的撤销/失败恢复。现有 MCP 多步骤调用不自动具有原子事务保证。

试听优先独立副本；临时提示复用独立预览层，不写 Note.color、不刷原生文字去模拟实时状态。使用 owner 隔离，原生选中/播放/拖动优先；关闭插件、换谱、撤销、隐藏和失效均清理。

### 2.5 性能原则

- 不在播放/鼠标移动时全谱分析；用版本化快照、局部索引、内容依赖失效与选区优先。局部改音仅重算相关声部、相邻和声/指法窗口；换调/改变角色可扩大范围。
- 多面板共享结果和任务，避免摘要、详情、AI 入口各扫描一次。隐藏窗口停止绘制/高频通知；任务可取消，旧结果不覆盖新版本。
- MIDI/音频实时路径只传有界事件和时间，不运行理论算法、FFT、文件读写或 UI 调用；过载报告丢失/精度不足，不无界积压。
- 首轮只读工具优先在停播时分析。播放时展示缓存结果，必要增量计算可分批/延后；大型离线任务采用 worker/辅助进程。
- 目标是测量后控制成本，不声称“零性能影响”或 DAW 硬实时。验收记录禁用/开启时输入延迟、GUI p95 耗时、音频欠载、内存与取消响应；现有高亮缓存性能不能代替新算法测量。

## 3. 对位、和声疑点与钢琴可弹性

### 3.1 第一版交互：只读、局部、可解释

选一段 → 选择/确认旋律、低音及其他声部 → 选择风格 → 分析。面板按“和声疑点 / 声部进行 / 演奏困难”分类，列出节拍、涉及音、依据、严重度与置信度；点击定位，循环试听上下文，允许忽略此处/此规则或修正角色与和弦解释。

不默认把全谱涂成告警色。使用小型可开关提示和稳定的列表；选择一个问题才展开证据与候选。沿用 HarmonyAssistant 的顶栏摘要/侧栏详情/悬浮、稳定区域、颜色配置和临时层原则，避免重新造成面板抖动、重叠和原生选择色丢失。

### 3.2 对位检测方法

先定义真实声部。谱表不是手；同一 voice 的和弦不是一条单旋律。对和弦内部旋律线可以显式指定最高/最低音规则，或用音高距离、连续性与用户角色约束的 DP 提出声部分配；有歧义就标记，不擅自认定。

检查攻击点、持续重叠与强拍，而不是只看垂直瞬间。候选规则：同向连续纯五度/八度、外声部隐伏五八、交叉/重叠、异常跳进及后续处理、导音/七音解决、持续不协和、声部间距与功能重复。平行与隐伏规则需标明比较的两个独立声部及前后音；同一声部的八度加倍不当作两条独立线。

以 TPC/调性计算音程身份，并使用半音核对；例如纯五度→减五度不等同于两个纯五度。反向进行、八度移位是否纳入规则由风格设定，不能直接照搬某库默认行为。参考 [music21 的规则边界](RESEARCH.md#三算法与媒体参考)，规则实现、测试与 UI 独立。

风格预设：严格对位（较严格声部规范）；调性钢琴/流行（允许惯用加倍、踏板织体）；爵士/色彩和声（扩展音与排列优先）。预设控制规则权重，不把所有音乐强行按同一传统教科书判错。

### 3.3 非和弦音与“影响味道”的音

和弦来源按用户选定解释、明确和弦表、已有 Harmony、算法候选排列；冲突并列提示，不自动认定原曲一定比当前编配更正确。

传统分类利用拍重、时值、进入/离开方式、邻接音、低音变化和解决：经过音、邻音、倚音、挂留、先现、延留等给出可能解释。长时强拍、无明显处理、与低音强烈冲突、破坏用户指定和弦特征的音提高疑点权重；短弱拍经过音降低权重。9/11/13、蓝调音、离调和弦、旋律持续音可有意存在。

输出“这里可能把希望的 Cmaj7 听感变成另一种色彩，原因是……”，而非“这个音错了”。持续旋律与变化低音分开评估，踏板残响可以跨和弦，不能只因上一和弦的音还在响就判定新和弦不合理。

无参考时只分析当前谱，标记和声解释不确定处。有原曲时，可添加局部和弦、旋律或段落材料，经手工/算法对齐比较。原曲与编配允许转调、删段、重复和节奏改写；没有对应就不做逐音“错音”比对。自动从原曲音频提取准确旋律/和弦另列后期任务。

### 3.4 分手、指法与可弹性

左右手来源优先级：用户明确分配 → 无歧义的分手符号锚点/区间 → 明确指法/角色 → 谱表启发式。分手符号只是线索；要定义起止边界、同 tick 多符号和重叠冲突。跨谱表记谱不强制换手，低谱表可承载右手旋律。

区分键仍按着、延音线连接、踏板声学持续。踏板响着不表示手指仍被占用；反之无踏板不能任意提前放开。给“按记谱严格保持”与“允许踏板下释放”的分析模式，第一版只提示，不擅自缩短谱音。

难度分三层：

- **静态：** 同手音数、跨度、黑白键几何、可用手指、同时保持冲突。舒适/最大跨度可配置，不能仅靠最高最低 MIDI 差。
- **动态：** 速度/rubato 对可移动时间的影响、跳跃距离、换指/拇指穿越、保持音限制、连奏要求、重复音、琶音与装饰音的顺序。
- **全段：** 连续高负荷、反复方向变化、左右手交叉与重新分配后的旋律连贯性。

第一版给跨度/跳跃和保持冲突。进阶用显式可调成本的 DP/beam 搜索指法和分手，输出少量候选与代价解释，允许用户锁住关键指法。HMM 文献可作参考，但学习参数和模型版本单独列为后续选项，见 [指法研究](RESEARCH.md#三算法与媒体参考)。

一手超过五个同时按键通常高风险，但滚奏、先放后按、拇指双键等例外必须由用户配置/确认；不把算法推测当作“保证可弹”。手的大小、经验、触键和意图差异无法从 MIDI 唯一确定。

### 3.5 配音建议

在锁定旋律、指定低音、和弦特征音、节奏骨架后，枚举局部八度移动、内声部替换、减少重复音、重新分手/滚奏等。成本兼顾声部连贯、和弦特征、跨度、跳跃、密度和用户风格；默认最多展示三种明显不同方案。

建议解释收益和代价，例如“把内声部移低八度，减小右手跨度，但中低频会更密”。修改音高、时值、声部或分手符号分别列差异。试听副本，接受后通过范围保护应用；未经用户选择不会覆盖配音。

## 4. 视频 MIDI 后处理与动态乐谱

### 4.1 推荐的双输出

原谱继续表达声部和记谱意图；读取**实际渲染/导出的 MIDI**，生成新文件与报告，不覆盖源文件。延音线、琶音、装饰、反复、演奏参数不能仅靠谱面名义时值推算。

优先输出：原音频 WAV/原演奏 MIDI 用于声音；视频 MIDI 或 gate manifest 仅控制瀑布流长度。这样可以明确保持原音频，同时改善显示。若视频工具不支持独立音频，需要另设“单 MIDI”模式并试听：CC64 保持相同并不证明缩短 note-off 后声音完全相同，释放包络、再触发、踏板阈值与渲染器会影响结果。

工具需允许按声部/角色/范围选择，前后对比、回放、保存预设和随机种子。没有角色信息时按 track/channel 配置，不凭高低音擅自判断旋律。

### 4.2 传统处理规则

1. 转成绝对事件时间，配对 note-on/off；note-on velocity=0 当作 off。同通道同音高重叠若无法唯一配对，保留并报告，不能猜着改。
2. 保持起音、音高、力度、tempo/meter、踏板、程序/通道与其他事件默认不变；只处理用户选择的 note-off/gate。
3. 先保护：明确持续旋律、无踏板关键连奏/和声连接、用户锁定音、已有特殊演奏事件、未知控制器语义。
4. 在 CC64 有效区间内，对允许释放的键设 gate：不短于最小秒数/拍长，不跨下次同音触发；考虑抬踏板时刻。踏板结束后的衰减不是可推断的完整声学长度。
5. 无踏板时默认轻微处理伴奏或用户指定重复/填充音，保护旋律与需要保持的低音；从乐句/织体预设取得 gate 比例。不存在“所有写满时值都可缩短”的通用规则。
6. 随机变化幅度小、可关闭、种子可复现；按角色/乐句相关变化，不给每个音独立大幅抖动。优先改变 release，不随机起音/速度/力度。
7. 重编码保持同 tick 必要事件顺序、源 PPQ、未知 meta/SysEx 和不处理的轨道。CC66/67、半踏板、全音符关闭等未实现语义须保护或明确标示，不简单忽略后继续改。

对每个可缩短音，候选必须满足 `原起音 < 新 off <= 原 off`，再叠加最小 gate、下一同音起音及用户保护约束；约束无交集就保持原音并说明原因。视频 manifest 与实际 MIDI 的 off 分别保存，避免把显示长度回写成演奏事实。

报告包括改动数、保护/歧义数、最大缩短、范围、参数、种子、源摘要和输出版本。可保存源 gate 与新 gate 的差异清单，重跑稳定、可恢复。

### 4.3 动态乐谱：仅远期记录

以后可将原生离线谱面渲染、展开播放位置、音频/视频时钟与滚动/翻页合成。需处理反复、跳转、速度曲线、跨系统、裁切、分辨率和字体；本轮不实现，也不先向播放回调加入录屏/编码。先保留 MIDI 派生输出的时间轴与片段映射，作为后续数据基础。

## 5. 多种编配方案的快速切换

### 5.1 可行性与三条路线

**可行，但建议以独立完整谱副本承载方案。** UI 可以看起来是“这段的 A/B/C”，内部不必让一个 Segment 同时拥有多套音符。

| 路线 | 用户体验 | 改动/风险 | 结论 |
| --- | --- | --- | --- |
| A：插件管理完整副本与谱页 | 自动建立/管理 A/B、定位同一范围、播放比较；仍可能切标签页 | 最低；须验证 read/write 保存副作用 | 合适的可行性原型，不等于最终同窗口体验 |
| B：插件方案 UI + 宿主安全副本工作区 | 同窗口切方案；独立谱实例、范围播放；停播切换 | 新工作区模块 + 克隆/视图/播放/生命周期少量接线；中风险 | 推荐最终路线，验证 A 的数据边界后再做 |
| C：核心音乐模型内嵌多版本 | 理论上可无缝显示/编辑 | 格式、Voice/Segment、Undo、布局、分谱、MIDI 全面影响 | 起步不采用，维护成本不符合最少修改目标 |

B 的接线控制目标是独立工作区、薄 PluginAPI 桥、现有视图/运输切换入口和构建注册。既有 `MasterScore::clone()` 可以作为候选基础，不能未经验证就断言包含所有个人属性与分谱关联。若安全克隆不可用，先建立独立序列化副本；禁止共享可变 Element 指针。

### 5.2 第一阶段体验和限制

选段 → “建立方案组” → 原始/A/B/C；每个方案可命名、备注、复制和试听。支持“上一/下一方案”和“从同一位置播放”；界面显示当前方案和未保存状态，避免把副本当原谱。

第一阶段限定同长度、同拍号、同小节边界，停播切换。每个方案使用完整谱副本，仅目标段可编辑，其余上下文锁定/标示。完整副本保留跨边界延音、踏板、调号/速度、反复和演奏上下文；试听有可配置预滚，段末按规则停止并释放。不要只复制选中小节 MIDI 后直接播放，遗漏进入段的持续音会改变比较。

快速试听可缓存已完成的渲染结果，但谱内改动或相关演奏参数变化必须失效。按键在谱编辑/输入框中不抢原快捷键；播放中提出切换，先安全停止并明确播放位置，再切到对应方案。边播边切会有跨段声学和时钟状态问题，另列远期。

### 5.3 保存与应用

方案工作区保存 groupId、基准快照、范围、每方案独立文件/状态、父方案、说明及比较缓存版本。关软件可恢复；搬动工作区有相对资源定位；打开缺失材料时提示但保留可读方案。

第一阶段最安全的接受方式是“将所选完整副本作为新成果谱”；后续再做“应用到原谱该范围”。局部应用必须检查原谱变化、范围外锁定项、旧值和跨界 spanner/连音/链接分谱；先拒绝不支持的复杂边界，不用整谱 MusicXML 重导入替代局部操作。现有比较工具可借展示，但不当作已存在合并引擎。

原谱后续编辑会让旧方案基准失效。提供重新建立组、只读比较、人工重新选择应用范围；自动重基不是第一版承诺。Undo 应能恢复一次应用，切换/试听本身不得写原谱或污染其撤销栈。

## 6. 节奏、速度与力度表达

### 6.1 Tap BPM：最早可独立交付

在节拍器旁添加 Tap 菜单 QAction 的工具栏入口；轻点按钮或焦点内快捷键采样，显示估计 BPM、拍单位、稳定度、重置及 ×2/÷2。点击本身不开始播放、不自动创建 TempoText。

用 QElapsedTimer 单调时间，只统计有效按下（排除自动重复/重复触发）。最近 8–16 次间隔，用中位数/MAD 或稳健拟合估算；起步先给粗值，连续稳定后提高可信度。长停顿重置序列，双击过短间隔不污染；用户可以回看/重置而不是自动被“纠正”节奏。

6/8 可选择每个八分/附点四分一拍，明确换算为宿主四分音符 BPM；例如附点四分 80 对应四分 120。可显示超出独立节拍器当前 20–400 范围的估计，应用时解释范围限制，不静默截断。

应用目标显式选择：只估计、独立节拍器、选中位置的速度标记。第一版前两项即可；写谱后续走原生速度编辑/Undo，保护已有速度标记。原生目标是一个独立估算器 + 菜单/工具栏和节拍器设置接线，不涉及合成器。

### 6.2 将三个高级意图分开

| 模式 | 已知条件 | 输出 | 主要歧义 |
| --- | --- | --- | --- |
| 表达已有谱 | 音高与节奏基本已知，可指定只敲旋律 | 力度和/或 rubato 候选 | 漏弹、装饰、声部错位、重复段 |
| 给定音高写节奏 | 和弦/音序已知，选择拍号、拍单位与允许细分 | 量化节奏草稿 | 自由速度与新节奏不能从不等间隔唯一分离 |
| 自由演奏转谱 | 音高、节奏、分手均不固定 | 后期的转写候选 | polyphony、踏板、连奏、tuplets、自由速度同时未知，复杂度最高 |

推荐先做第一种，再做第二种。可借鉴 [PiCoDemo](https://github.com/lynnzYe/PiCoDemo) 的“输入按键表达时机/力度，音高来自已有谱”思路，允许不准确弹出音高。它不等于任意演奏自动转成可靠记谱；[MaskedExpressiveness](https://github.com/lynnzYe/MaskedExpressiveness) 属学习模型，另列后期。

### 6.3 离线导入先行

先用演奏 MIDI 文件 + 目标选段：用户指定角色/起点/锚点，可比较起音时间、力度和对应可信度，修正错配；无需新增设备捕获路径。

传统对齐使用按起音聚类、单调 DP/DTW、允许漏弹/多弹的成本、音高/节拍/声部特征，已知按键模式则只对起音序列。和弦滚奏聚类窗口随速度/用户参数调整，不把滚奏每个音强行变成一个新拍。重复段使用 occurrence/展开位置与显式锚点，低置信度部分保留未匹配。

参考 [Parangonar](https://github.com/sildater/parangonar) 的传统匹配方向；若集成先锁定适用路径与版本，不强制带入神经模型。选择半段/旋律录入时，未演奏声部按规则插值而非伪造逐音测量。

### 6.4 rubato 候选

对齐到已知节奏后，以 `四分 BPM = 60 × Δ谱面四分拍 / Δ实际秒` 构建分段速度。用可靠锚点、单调映射与局部稳健平滑，保留有意句尾拉长，避免把每个手指错位都变成速度变化；设置力度/速度分开启用和应用强度。

保持目标段总长度/边界速度或允许伸缩是显式选项。装饰音/同时和弦不用于零长度除法；有限原生可编辑点映射到实际可写入的位置，不宣称连续曲线能无损写到任意细粒度。现有 TempoText 与已锁曲线保留，冲突可试听比较。

自由节奏录入模式先选择稳定拍网格及允许二分/三连音等细分，输出 rhythm 草稿；若要同时推断 rubato，至少需要锚点或预设约束。不能从同一串按键间隔同时“自动确定唯一正确时值和速度”。

### 6.5 力度候选

保留设备原始 velocity，支持键盘曲线/用户基准校准。分声部建立趋势，旋律、低音、内声部使用可调相对权重；未输入声部可采用局部插值与衰减，显示“推算”来源。不要将单键点击的 velocity 原样复制给同时所有音。

需要区分原生绝对力度、相对力度、动态记号与最终合成结果；通过当前演奏基准换算目标值，保护手工锁定音/动态。先展示 A/B 播放，之后一次应用到指定范围并支持 Undo。力度分配本身不改变音高/记谱时值。

### 6.6 实时捕获：后续宿主配合

捕获为专门会话，不让录入一边驱动普通音符输入、一边又作为表达样本写谱。设备由宿主单一拥有，向捕获模块分发事件；外部 helper 单独打开 MIDI 口可能在 Windows 与宿主抢占，必须验证，不能默认两边同时监听。

事件记录 source/device/channel、sequence、会话相对微秒、时钟口径、on/off/velocity/CC64、溢出与延迟校准状态。优先保留后端时间戳并映射单调时钟；无可靠后端时间戳的路径可用入口时钟但明确精度。GUI 心跳/排队后收到时间不能作为精细演奏时间。

原生控制目标：独立 capture session/缓冲模块，适配相关驱动输入与 Seq/GUI 路径，再提供薄桥；实际后端差异使修改量大于一个 QML 信号。音频回调不执行对齐、日志或磁盘写入。断开、队列溢出、持续按键、停止时丢 note-off 都有明确关闭/恢复策略，原有 P 键盘和 MIDI 输入在模式关闭时完全走原路径。

实时监听与离线回填可分开：监听为了听见/看到，最终候选用完整会话离线对齐，避免实时预测的下一拍未知问题。首版不承诺复杂反复/任意跳段的实时跟随。

## 7. 原曲播放器与频谱工作区

### 7.1 基础版的有用范围

打开本地原曲 → 播放/暂停/定位 → 波形、A/B 循环、书签 → 将一个片段手动关联到谱选区。也允许完全独立播放。用户可分别控制原曲与谱播放的音量/静音，明确当前运输焦点；输入框和谱编辑状态下不抢原有空格/快捷键。

先验证 Qt 媒体部署：实际宿主 Qt 版本、Windows 后端、解码格式、seek 和速度行为。初版可优先支持经过实测的 WAV，再扩展 MP3/FLAC 等格式；不承诺平台默认全部支持。变速不变调若后端不保证，则明示能力或单独增加经许可核查的 time-stretch 库，不把 playbackRate 当作保证。

原曲默认外部引用，旁车存资源摘要、书签、片段和位置；移走后可重定位。不要自动把整曲二进制塞进 MSCZ，防止文件膨胀。现有旧 WaveView 可作代码参考，不能视为已经可复用的完整媒体引擎。

### 7.2 对应与同步

第一版手动起止锚点：谱 tick/拍与录音秒，允许仅某段已对应；不要按整曲均匀拉伸强行对齐。进阶使用分段单调映射，记录重复段 occurrence、一段录音对应多次谱重复、删段/移调等差异。对应精度分段落/拍/逐音，不冒充更高精度。

先提供点击原曲位置定位谱、点击谱关联位置 seek 原曲；随后做选项式联动播放。设一个主时钟，另一侧仅在超差/seek 时校正，记录 drift 和 seek 延迟。两个独立播放器不能自动达到采样精度；频繁硬 seek 会破坏听感。统一音频输出混合/精确时伸需要另一个高成本阶段，不是基础播放器前置条件。

片段可保留前后余量、循环和速度设定；联动关闭时完全独立。播放参考不隐式改谱速度标记/演奏编辑值。

### 7.3 波形与频谱

参考 [WaveTone 官方帮助](https://ackiesound.ifdef.jp/doc/wthelp/index.html) 的听写流程，自研需要的子集，不嵌入许可不明的程序。

波形多级降采样；STFT/Hann、对数频率/钢琴音高参考线、可选左右声道/单声道/差分，片段循环与频谱光标相互定位。解码与 FFT 在 worker，分块计算、可取消、优先可见片段，LRU 内存/磁盘 tile 缓存按源摘要和算法参数版本失效。

频谱是证据视图：谐波、混响、打击乐及多个音重叠不能直接当成准确音符。不要点一条亮线就未经核验增添谱音。频率/音名、基频候选与不确定度可显示；音高移调/调律偏移可配置。

### 7.4 后续音频分析

传统 chroma/HPCP + 和弦模板、局部节拍/起音候选可产生参考材料，保留原曲时间范围、置信度和算法版本，经 alignment 与 HarmonyAssistant/对位工具共享。低音、旋律分离和精确复调转写另评估，不能依赖频谱亮线解决。

未来 AI 使用相同 materials/assertions 接口；本地分析和听原曲不需要 LLM。原曲上传/云服务另按用户明确选择，当前规划默认本地文件处理。

## 8. 工程交付与验证

### 8.1 拆分和可合并性

插件按领域独立目录；公共契约/轻量工具放可复用包，避免复制 HarmonyAssistant 算法与配置。后续候选目录如 CounterpointAssistant、ArrangementVariants、PerformanceCapture、ReferencePlayer、MidiPostProcess 仅为提议，本轮不建立空实现。

原生增加通用快照/捕获/媒体/副本桥，不在 libmscore 填音乐规则，不混入解析模型、UI 布局或第三方网络服务。默认关闭的新入口没有后台任务；不改原版选择颜色、选区粗细、P 键盘与播放路径。

每项真正实施前拉取两仓库并检查并行任务；提交只包含自己负责的文件/片段。涉及软件修改时，同步 personal/USER_GUIDE.md、开发日志、源码索引、commit 定位及必要版本发布；VERSION/branding 保留 Kumo/Freddd13 标识，新工具栏复用菜单 QAction。无冲突且验证充分后才按仓库规则提交/推送。

本轮只有本地规划，没有新增/改变可用功能，所以不把设想写成 USER_GUIDE 中已发布的功能，也不改 personal/VERSION。真正实施的用户说明维护列入各任务交付条件。

### 8.3 还不能下定论的事项

最值得先做验证而非完整开发的是：安全克隆/保存副作用；完整快照及应用能力；实际 MIDI 设备时间戳和端口所有权；媒体后端/格式/seek/变速；目标视频工具是否支持独立音频/显示 MIDI。上述失败可调整路线，不要求先重写核心。

具体排期应由选定的一个小交付及实际测量决定。当前草案不将高级转写、联合音频时钟、自动重基和自由跳段实时跟随混成一项“最终插件”。
