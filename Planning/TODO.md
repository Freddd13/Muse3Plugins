## 0. 共用交付约定

每项实施的完成条件：限定范围 → 原型/实现 → 相应测试与实际交互验证 → 用户可查的说明/限制 → 独立提交。改宿主时还须同步 USER_GUIDE、开发日志、源码索引和版本/品牌规则；没有新增发布不虚增版本。不能顺手修改别的插件，也不能删除已有文件或移除功能。

记录模板：`任务 ID / 选定日期 / 范围 / 依赖 / 插件与宿主提交 / 测试证据 / 未验证设备与限制 / 用户说明位置`。并行任务修改同一文件时先协调，以独立片段提交，禁止覆盖他人未提交内容。

## 2. 对位、和声疑点、配音与指法

- [x] **ANA-01 · P0 · M：只读和声疑点。** 使用用户选定和弦/算法候选与局部拍重、持续、解决规则；识别常见非和弦音可能解释。交付：定位列表、证据/置信度、忽略/人工纠正；无原曲也工作，9/11/13 与挂留不被一律判错。依赖 CORE-01；不改原谱。
- [x] **ANA-02 · P0 · M：只读对位检查。** 明确声部来源、平行五八/外声部隐伏/交叉/导向等规则及风格预设。交付：前后音对可核查；和弦加倍、反向运动、纯五→减五等边界测试。依赖 CORE-01；与 ANA-01 可独立开关。
- [x] **ANA-03 · P0 · M：基础可弹性提示。** 分手线索、舒适/最大跨度、保持冲突、速度相关跳跃；严格保持/踏板可释放两种解释。交付：手分配歧义提示、个人参数、滚奏例外；跨谱表不自动换手。依赖 CORE-01，不生成或改写指法。
- [x] **ANA-04 · P2 · L：指法/分手序列候选。** 可调规则成本 + DP/beam，手指占用/黑白键/移动时间；锁定用户指法。交付：少量候选、代价解释与人工核查案例，不能声称保证可弹。依赖 ANA-03；写入标记另依赖 CORE-02。
- [x] **ANA-05 · P2 · L：排列与局部配音候选。** 锁旋律/指定低音/和弦特征，枚举八度、内声部、重复音及换手方案。交付：最多三种不同方案、收益/代价、独立试听、受保护应用与 Undo。依赖 ANA-01/03、CORE-02；副本试听复用 VAR 能力或独立候选副本。
- [ ] **ANA-06 · P2 · M：参考材料差异。** 支持局部原曲和弦/旋律/段落说明及手动对应。交付：当前编配/参考并列、来源版本与覆盖，转调/重复/无对应明确标示；材料更新不自动改谱。依赖 CORE-01；自动音频转写不在此项。

## 3. 视频 MIDI 后处理

本轮 P0 已改为软件 MIDI 导出内的保守裁剪、视觉对比、固定种子微随机与原版本导出。原 MIDI-01 的实际目标视频软件验证及后续角色／乐句优化仍未完成，不将它们勾选为已验收。

- [ ] **MIDI-01 · P0 · S–M：目标视频工具小样验证。** 用实际常用软件验证独立音频 + 视频 MIDI、踏板显示/音频行为、同音重复和 MIDI 时间口径。交付：两种管线的试听/画面样例；确定首版输入输出与不能保证的声音效果。起步只用导出的 MIDI，不改宿主。
- [x] **MIDI-02 · P0 · M：确定性 gate 处理。** 先无随机：只改允许音的 note-off，保护起音/tempo/踏板/其他轨道和未知事件；歧义同音配对保留。交付：新文件、差异报告、源文件摘要不变；CC64/无踏板/同 tick 排序/PPQ 与 meta/SysEx 测试。依赖 MIDI-01。
- [ ] **MIDI-03 · P1 · M：角色预设与小幅随机。** 声部/范围保护、乐句相关变化、种子复现、最小 gate 与下一同音边界。交付：前后比较/参数保存，原音频与显示 MIDI 分离使用说明。依赖 MIDI-02；没有角色数据时仅 track/channel 选择。
- [ ] **MIDI-04 · P1 · S–M：插件便利入口。** 从当前谱生成有效演奏导出或选择已有 MIDI，调用离线工具/打开输出目录。交付：失败/取消不更改原谱路径、dirty 或撤销栈；先验证 writeScore 副作用，必要时提通用安全导出桥。依赖 MIDI-02，不强迫安装此入口才能使用工具。
- [ ] **VID-01 · P3 · XL：动态乐谱视频。** **仅排队记录，另做设计。** 评估离线排版帧、翻页/滚动、展开反复、速度曲线、音画时钟与编码管线；不把录屏/编码放入实时播放回调。可复用 MIDI/REF 时间映射。

## 4. 多方案工作区

- [x] **VAR-01 · P1 · M：副本安全验证。** 核查 readScore/writeScore 的路径、dirty/Undo；验证 MasterScore 克隆的个人演奏数据、分谱/链接、tie/spanner、调性/速度。交付：能力矩阵、隔离证据和 A/B 路线结论；不修改核心音乐模型。此项是决定宿主修改量的关卡。

- [x] **VAR-03 · 已按新计划实施：一个MSCZ内的分段／声部方案。** 0.42采用当前组合使用普通乐谱、未用写法压缩保存的方式；支持停播切换、撤销、资源／分谱、主方案入口和旧项目导入。原完整副本插件保留。具体范围及检查见REPAIR_IMPLEMENTATION.md和用户说明第13章。
- [ ] **VAR-04 · P2 · L：比较和局部应用。** 基准/旧值/范围锁校验；处理或拒绝跨界延音/spanner/链接情况，复用比较展示但独立验证合并。交付：原谱变化导致候选过期、明确差异、一次 Undo/读回。依赖 CORE-02、VAR-02；首次可仅“将副本另存为成果谱”。

## 5. Tap 与演奏表达

- [x] **TAP-01 · P0 · S：Tap BPM 估算与节拍器入口。** 独立单调计时、稳健估算、重置、倍/半速和拍单位；菜单 QAction 放节拍器旁。交付：6/8 附点拍换算、重复键/长停顿/异常点击测试；估计与独立节拍器应用，默认不写速度记号。无需 CORE 服务。
- [x] **TAP-02 · P1 · S–M：Tap 结果写入指定速度。** 显式目标位置、现有 TempoText 保护、原生 Undo/读回；不偷改全谱或当前播放速度曲线。依赖 TAP-01、适用的 CORE-02 编辑路径。
- [x] **EXP-01 · P1 · M：已知谱与演奏 MIDI 离线对齐。** 目标范围/角色/锚点，起音聚类 + 传统 DP/DTW，显示漏/多弹和低置信度。交付：逐拍/逐音对应可手改，重复 occurrence 不混淆；仅录入旋律也有效。依赖 CORE-01；不使用模型补全。
- [x] **EXP-02 · P1 · M：力度趋势迁移。** 校准 velocity、声部权重和局部插值；保留 raw 数据，候选预览，保护手工力度/动态。交付：来源明确的 A/B、应用强度、原生实际值换算、读回/撤销。依赖 EXP-01、CORE-02。
- [x] **EXP-03 · P1 · M–L：rubato 迁移。** 已知节奏上的单调时间映射/局部稳健平滑，边界速度/段长约束，已有速度保护。交付：句尾拉长与误触区别、tempo map 预览、可写入点限制、暂停边界应用与 Undo。依赖 EXP-01、CORE-02；不同时自由推断节奏。
- [ ] **EXP-04 · P2 · L：实时 MIDI 捕获。** 专用会话、设备单一所有权、后端时间戳映射、有界事件缓冲、普通输入模式隔离。交付：实机设备/输入驱动证据、忙 UI 时间准确性、断开/溢出/缺 off 处理与原有 MIDI/P 键盘回归；精度/校准说明。依赖离线流程已可用；不在回调中跑分析。
- [x] **EXP-05 · P2 · M–L：固定音高的点击表达。** 从已有和弦/音序取音高，任意键表达时机/力度；监听与完整会话离线回填分开。交付：旋律控制其他声部的时间/力度候选，遗漏/重敲修正；实时预测局限明确。依赖 EXP-01/02/04，参考 PiCo 的传统路径。
- [x] **EXP-06 · P2 · L：给定音高写节奏。** 先选拍网格与细分，生成 rhythm 草稿；rubato 独立模式、tuplets/滚奏有边界。交付：可编辑候选及记谱时值真正写回，不靠视觉宽度模拟；低确定度不直接改谱。依赖 CORE-02、EXP-01/04。
- [ ] **EXP-07 · P3 · XL：自由演奏转谱/复杂实时跟随。** 另评估自由速度、多声部、任意跳段与重复；明确训练模型和纯规则路线，不能把 EXP-06 成果宣传成已解决此项。

## 8. 建议分批选择

| 批次 | 建议可选包 | 边界/成功标准 |
| --- | --- | --- |
| A，最快日用 | TAP-01；或 MIDI-01/02 | 各自独立；可估 BPM / 可产生可复现视频 MIDI；不动乐谱 |
| B，编配检查 | CORE-01/04 + ANA-01/02/03 | 选段分析有可信证据、能定位、无原曲可用；不开自动改音 |
| C，参考与表达 | REF-01/02；或 EXP-01/02 | 可听原曲循环定位 / 可迁移演奏力度并撤销 |
| D，试写比较 | VAR-01/02 → 评审后 VAR-03/04 | 独立副本安全，停播 A/B 比较，同窗口体验和局部应用逐步加 |
| E，进阶演奏 | ANA-04/05、EXP-03/04/05/06、REF-03/04/05 按需选 | 各有数据/设备/性能关卡；不以一个巨大版本交付全部 |
| F，后续构想 | VID-01、REF-06、EXP-07、VAR-05、AI-01 | 另立设计/原型，前面工具不依赖它们 |

优先级可以由你的实际需求改动；批次不是强制顺序。例如只要 Tap，无需先完成全部 CORE；只想听原曲，也不必等待指法算法。
