# 传统建议的计算方法

指法采用同时按键组合与前后组合的代价搜索，参考[钢琴指法研究的5.4节](https://arxiv.org/html/1904.10237)。每个物理琴键使用一个手指，持续按住的音保持该手指；同音多声部合并为一个琴键。和弦内部按手指顺序枚举，逐组保留最多32条状态，最后提供至多三种结果。

代价分成同时伸展、前后移动、穿跨指、黑键上的拇指或小指、同音换指。这里使用可调整的个人预设；论文中的统计参数需要带指法的训练资料，本轮权重由设置直接指定。

分手和可松开的保持音复用`PianoHands`，与编配检查和MIDI松手处理共用物理按键判断。已有分手标记及用户指定优先，踏板支持提前释放时再比较后续按键。几何表示使用白键位置及黑键的半格位置，时间参与移动代价。连续负担的设计参考[钢琴减难研究](https://arxiv.org/abs/1808.05006)中对顺序、手位与速度的讨论。

配音尝试有限的八度变化，重新运行现有和声、对位和按键检查，优先保留改善演奏负担的写法。对位修改限于当前起音组已有音级，利用拼写及连续声部检查前后进行，并比较修改前后的其它问题。规则对照[music21声部进行示例](https://music21.org/music21docs/moduleReference/moduleVoiceLeading.html)。

代码入口：`ArrangementAssistant/Suggestions.js`。宿主只读取数值、运行可取消的规则任务和准备原生候选；音乐规则继续独立保存。选段入口前尚在按住的音以`contextOnly`提供，供判断手指占用。已有指法或分手互相冲突、当前组合超出五指或个人跨度时，该处在结果说明中列出，保留原谱供用户校正。
